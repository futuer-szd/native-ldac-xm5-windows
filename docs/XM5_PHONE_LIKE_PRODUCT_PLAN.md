# XM5 手机式 Windows 产品总计划

更新日期：2026-08-13

依据：`docs/HANDOFF_2026-08-13_connective-sync.md`、

## 1. 总体目标

最终产品需要在 Windows 上为 Sony WH-1000XM5 提供接近连接手机时的使用体验：

- 无论先开启 Windows 蓝牙还是先开启 XM5，都能自动发现连接并进入可用状态；
- 关闭再开启蓝牙、关闭再开启 XM5、登录时已经连接等顺序都能自动恢复；
- 每次物理连接后执行一次初始音量同步，以 XM5 当前音量为准；
- 连接后在 Windows 中提供正常可用的输出设备，并在后续 HFP 阶段提供正常可用的输入设备；
- 在有媒体播放、媒体暂停以及可行时的无媒体状态下实现双向音量同步；
- 媒体存在时支持播放、暂停、继续、上一首和下一首手势；
- 内部允许使用 Microsoft 驱动、Native 驱动、连接期或媒体期切换等不同实现，用户侧必须无感；
- 后台稳定、低占用，UI 关闭后核心连接与播放能力仍然工作；
- 参数、UI 和音质能力在核心生命周期稳定后继续按既有要求完善。

## 2. 产品架构

采用“内核驱动 + 低占用后台宿主”的系统级架构，不把全部产品策略压入内核：

1. **`LdacNative`**：负责 A2DP/LDAC 蓝牙传输。
2. **`NativeLdacAudio`**：提供稳定的 Native LDAC Windows 输出端点。
3. **AVRCP 驱动层**：根据真机可行性结果采用连接期接管、预绑定或媒体期接管。
4. **机器级后台宿主**：负责 ACL generation、PnP、驱动 owner、传输 worker 和故障恢复。
5. **用户会话宿主**：负责 Core Audio 音量、媒体键、默认设备策略及 UI IPC。
6. **UI**：只负责配置、状态展示和诊断，不承担连接、播放或控制通道保活。

PnP、Driver Store 和驱动绑定只允许由提升的机器级组件执行；用户会话组件不得直接修改驱动状态。

## 3. 分阶段实施

### 3.1 阶段一：产品运行时与完整连接生命周期

- 将现有 daily host 与 handoff host 收敛为明确的机器级宿主和用户会话宿主边界；
- 以 XM5 真实 ACL connect/disconnect 作为唯一物理连接边界；
- 每次物理连接创建新的 ACL generation，旧 generation 的 worker、回调、租约和写操作全部失效；
- 覆盖以下连接顺序：
  - Windows 蓝牙已开，再开启 XM5；
  - XM5 已开，再开启 Windows 蓝牙；
  - 登录时 XM5 已连接；
  - 关闭再开启 XM5；
  - 关闭再开启 Windows 蓝牙；
  - Windows 睡眠/唤醒及用户登录/注销；
- ACL 连接后目标 5 秒内发布可用输出端点；断开后立即停止新请求，并在 5 秒内报告 unplugged；
- 默认不抢占 Windows 默认输入/输出设备，后续在 UI 中提供可配置的自动默认设备开关；
- 所有失败必须有界收敛到健康 Microsoft 基线或明确 disconnected 状态，不允许无限 PnP 重试。

### 3.2 阶段二：稳定输出设备与 LDAC 播放

- 保留单一 Native LDAC 输出端点，同一 ACL 内播放、暂停、停止和重新播放不重新枚举端点；
- 播放开始后沿用已验证的 RenderDemand、engine-ready、AVDTP 和 PCM 生命周期启动 LDAC；
- 暂停时在原 AVDTP 会话执行 `SUSPEND`，恢复时执行 `START`；真正停止时才执行有界 `CLOSE`，输出端点继续存在并等待下一次播放；
- 无媒体时默认不建立正常 LDAC 媒体流，除非阶段四的自适应保活方案通过门禁；
- 默认音频策略保持 transparent unity，不增加固定衰减、EQ 或常态 limiter；
- 支持 Auto/HQ/SQ/MQ、44.1/48/88.2/96 kHz、16/24-bit 和真机已确认支持的声道模式；
- 参数不支持时明确禁用或报告，不静默回退为不同格式。

### 3.3 阶段三：连接期音量与媒体控制

#### 3.3.1 空闲 AVCTP 可行性与 owner 方案

- 加固空闲 AVCTP 实验工具，在同一个 observer handle 和同一条 AVCTP channel 内完成：
  - OPEN；
  - capability/absolute-volume 事件接收；
  - XM5 手势观察；
  - `SetAbsoluteVolume` 写及回显；
  - 通道自然保持时间记录；
- 补测连接后 delay 1/5/15 秒三档；
- 分别验证两种真实产品时序：
  - observer 预绑定后建立物理连接；
  - Microsoft 完成物理连接后再切换 observer；
- 根据真机结果确定最终内部 owner 策略。实现方式不暴露给用户，任何切换都必须自动完成并自动恢复。

#### 3.3.2 音量合同

- 每个新的 ACL generation 首次取得 XM5 绝对音量后，以 XM5 为权威更新 Windows；
- 同一物理连接内 AVCTP 重建、驱动切换或媒体暂停不得再次抢占 Windows 音量；
- PC 音量变化发送到 XM5，XM5 侧滑更新 Windows 音量；
- 覆盖静音、0%、100%、快速连续操作、端点回读和回环抑制；
- 音量同步激活后采用单增益模型，切换必须在安全音频边界完成，并使用短渐变避免双衰减、爆音或音量突跳；
- AVRCP 不可用时恢复 Windows 软件音量路径，控制面故障不得破坏 LDAC 播放。

#### 3.3.3 媒体手势

- 将 XM5 播放、暂停、继续、上一首和下一首手势路由至当前 Windows 媒体会话；
- 按键 press/release 必须去重，单次手势只触发一次动作；
- media session 不存在时安全忽略不适用动作，不启动或伪造媒体播放；
- owner lease 或 ACL generation 失效后禁止继续注入媒体键。

### 3.4 阶段四：无媒体音量同步决策门

无媒体双向同步不预设一定使用静音保活，按真机数据决定。

#### 纯 AVCTP 通过条件

- 两种开机/连接顺序各连续 10 轮成功；
- 空闲控制通道自然保持至少 30 分钟；
- 双向音量与首次 XM5 权威同步均能工作；
- 断开、关机、蓝牙关闭后及时释放，且 Microsoft 基线可恢复。

#### 自适应保活后备方案

纯 AVCTP 失败时，开发最低占用的不可闻静音/控制保活原型：

- 用户侧仍显示无媒体播放；
- HFP 激活、XM5 断开、蓝牙关闭或系统休眠时立即释放；
- 20 次连接循环与 8 小时空闲稳定测试无故障；
- 无可闻输出；
- 后台平均 CPU 低于 0.5%；
- 三轮 4 小时 A/B 电量对照中，额外耗电不超过 2 个百分点或基线耗电的 10%。

若任一门禁不通过，正式取消“无媒体期间持续双向同步”，产品保留每次连接首次同步以及媒体存在/暂停期间的双向同步，不继续扩大为完整自研蓝牙 controller 栈。

### 3.5 阶段五：UI、配置与音质

当前状态：只读 UI 基础切片和受限质量 IPC v1 已完成。UI 读取 current daily host 的
原子状态和最近 transport result，显示连接、播放、统一音量、HFP 监视、故障、最近
格式和码率；质量只允许 HQ/SQ/MQ，通过同用户命名管道提交，配置在下一次安全媒体
会话边界应用；关闭 UI 不影响后台。格式/EQ 写配置仍关闭。

- UI 显示连接阶段、ACL generation、当前传输 backend、AVRCP owner、音量权威、实际 LDAC/RTP 码率、最近错误和恢复状态；
- 提供质量、采样率、位深、声道模式、音量同步模式和自动默认设备配置；
- UI 关闭后连接、播放、音量与媒体键功能继续工作；
- 配置使用版本化 schema 和原子写入；后台遇到非法配置时继续使用最后一次有效配置并报告错误；
- 完成 96 kHz/24-bit、Auto ABR、暂停恢复和长期播放真机门禁后再开放对应选项；
- Windows 声音设置只需要展示系统自带的基础参数，更详细的调节与诊断放在项目 UI；
- EQ、音质处理、limiter 等增强继续按既有要求开发，但不得阻塞核心生命周期交付。

### 3.6 阶段六：输入设备与 HFP 自动切换

本阶段安排在稳定输出、音量控制和 UI 之后，但属于最终产品必做范围。

- 复用 Windows 原生 XM5 Hands-Free capture，不自研完整 HFP/SCO/eSCO 栈；
- 产品基线要求配对后存在正常可用的 XM5 Hands-Free 输入端点；若本机历史配对损坏，通过明确的人工重新配对恢复，不自动删除用户配对；
- XM5 连接后同时显示 Native LDAC 输出设备和 Windows Hands-Free 输入设备；
- 用户会话宿主通过 Core Audio 会话通知检测 XM5 麦克风被应用实际打开；
- 麦克风激活时停止并释放 LDAC，会话内部把同一 Native LDAC 输出端点降级桥接到 Windows HFP render；
- 麦克风结束并稳定 2 秒后释放 HFP 输出；若仍有 RenderDemand，则自动恢复 LDAC；
- HFP 模式使用 Windows 通话音量，返回 LDAC 后不得重复执行本 ACL generation 的首次 XM5 音量抢占；
- 输入端点丢失时只进行有界检测与报告，不循环重启 PnP、音频服务或自动删除配对。

### 3.7 阶段七：稳定性、安装与发布

- 完成至少 100 次 XM5 开关机循环；
- 完成至少 50 次 Windows 蓝牙关闭/开启循环；
- 覆盖睡眠/唤醒、登录/注销、宿主崩溃、播放中断连和驱动切换失败；
- 完成 8 小时 LDAC 播放、8 小时空闲连接和 LDAC/HFP 往返 soak；
- 音量传播目标低于 300 ms，媒体键响应目标低于 250 ms，ACL 后端点出现目标低于 5 秒；
- UI 关闭时机器宿主与用户会话宿主合计平均 CPU 低于 0.5%，工作集低于 100 MB；
- 任意故障都撤销旧 generation 写权限，停止旧 worker，并收敛到健康 Microsoft AVRCP 或 disconnected；
- 最后完成安装、升级、精确回滚、无残留审计、Driver Verifier 和正式签名。

## 4. 公共状态与配置接口

### 4.1 统一运行状态

运行时对 UI 和诊断面发布以下逻辑状态：

- `Disconnected`
- `Preparing`
- `Ldac`
- `IdleKeepalive`
- `Hfp`
- `Degraded`
- `Restoring`

状态快照至少包含：

- ACL generation；
- 输出/输入端点可用性；
- 当前 transport backend；
- AVRCP owner 与 channel 状态；
- 当前 volume authority；
- 当前音频格式与 LDAC 质量；
- 最近错误、恢复动作和时间戳。

### 4.2 配置

配置能力包括：

- LDAC 质量与格式；
- 音量同步模式；
- 自动默认输出/输入开关，默认关闭；
- HFP 自动切换开关；
- 日志与诊断级别。

机器宿主与用户会话宿主之间使用受限 IPC。用户会话宿主不得直接执行 PnP、Driver Store 或管理员驱动操作。

## 5. 测试与验收场景

每个阶段都必须同时具备离线合同测试和受控真机门禁。最终验收至少覆盖：

1. 蓝牙先开、XM5 后开；
2. XM5 先开、蓝牙后开；
3. 登录时 XM5 已连接；
4. 同一连接内播放、暂停、继续、停止和重新播放；
5. PC 与 XM5 两侧快速调节音量；
6. 静音、0%、100% 与重连首次同步；
7. 播放、暂停、上一首和下一首手势；
8. 播放中关机、蓝牙关闭和宿主强制终止；
9. Windows 睡眠/唤醒；
10. 后续阶段中的麦克风启动、LDAC→HFP、HFP→LDAC；
11. 安装、升级、卸载和恢复 Microsoft 基线。

## 6. 默认决策与范围边界

- 首个可交付版本以 PC 单连接为验收基线；手机多点连接作为后续独立兼容阶段；
- 默认不修改 Windows 默认输入或输出设备；
- 初始音量权威按每次物理 ACL 连接计算，以 XM5 为准；
- 核心架构采用驱动与低占用后台宿主协同；
- 无媒体同步由纯 AVCTP/自适应保活数据门禁决定；
- HFP 在输出、音量控制和 UI 完成后实施；
- Direct-PDO、完整自研 HFP 和尽量纯内核的产品策略继续冻结；
- 旧路线文档保留为历史和实验依据，本文件作为新的产品级总体目标与执行顺序。
